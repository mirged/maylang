- **Compiler and tooling reference** — the active compiler and language server are written in Maylang; Rust/C provide the source-only bootstrap.
- Build host: Linux x86-64 with Rust and GCC or Clang; Python 3 and binutils readelf are used by verification scripts.
- Bootstrap from the repository root: `sh toolchain/rust/build.sh`.
- Compiler launcher: `toolchain/mayc/mayc_new`; the launcher builds and caches the compiler on first use. Keep runtime/prelude/native sidecars and the runtime directory with the compiler.
- Compile: `toolchain/mayc/mayc_new examples/hello.may -o /tmp/maylang-hello`; run: `/tmp/maylang-hello`.
- Default output removes a final `.may` suffix; other suffixes receive `.out`.
- `-h`, `--help` — print command-line help and exit.
- `-V`, `--version` — print the compiler identity/version.
- `-o PATH`, `--output PATH` — select output path.
- `--check` — expand imports, parse, strictly check and resolve names without producing an executable.
- `--strict` — enable strict checking, the default.
- `--legacy` — disable the strict pass for legacy untyped sources; name resolution and mutability checks still apply.
- `--raw` — omit runtime, native library and prelude.
- `--runtime full|core|none` — select runtime; none is equivalent to raw; full defaults on x86_64-linux and clang-llvm, core on other native targets.
- `--time` — report compilation-stage timings to stderr.
- `--target TARGET` — select one of the supported targets listed below.
- `--emit-llvm` — write textual LLVM IR when selecting clang-llvm; without explicit output, a final .may becomes .ll.
- `--dump-expanded` — print import-expanded source and exit.
- `x86_64-linux` — default ELF64 target with full, core or raw runtime.
- `arm64-linux` — ELF64 with core or raw runtime.
- `riscv64-linux` — ELF64 RV64IM with core or raw runtime.
- `arm64-macos` — macOS 11+ Mach-O ARM64 PIE, loaded through dyld with core/raw runtime; ad-hoc signing required on macOS: `codesign --force --sign - output`.
- `x86_64-windows` — PE32+ with core kernel32 imports or raw output.
- `clang-llvm` — experimental direct LLVM IR and linked Linux x86-64 executable with the full Maylang runtime; does not support fibers, typed extern FFI, raw or core mode.
- LLVM executable generation requires Clang, linker and libc development files; `CLANG` chooses an alternative Clang executable. Emitting IR or checking sources does not require Clang.
- Cross-target emission does not make the compiler itself run on another host. the [native target suite](../docs/NATIVE_TARGETS.md) runs signed macOS ARM64 and Windows x86-64 fixtures through real loaders; emulator checks separately cover all five direct targets.
- Full runtime supports integers, boxed floats, UTF-8 strings, lists, maps, records, closures, structured errors, fibers and native C interfaces on Linux x86-64.
- Core runtime supports tagged integers/Booleans/nil/strings/lists, direct functions, loops, console output, indexing/mutation, ASCII case conversion and integer/string helpers.
- Core helpers include `str`, `substring`, `trim`, `repeat`, `range`, `sum`, `clamp`, `gcd`, `lcm`, `alloc` and `memcpy`; signatures/implementation are in [corelib](../toolchain/mayc/runtime/corelib.may).
- Core allocation retains heap chunks of at least 1 MiB until process exit, with a 256 MiB cap and no individual free/GC. [Explicit scratch arenas](../docs/CORE_MEMORY.md) reclaim capacity on reset, invalidating their returned pointers. Overflow and division by zero print a diagnostic and exit 70.
- Core compilation diagnoses unsupported closures, maps/records, floats, exceptions, fibers and FFI before output is written.
- ARM64/RISC-V raw subsets support integer/literal-string operations, globals/locals, direct calls, tail self-calls, loops, addresses, memory loads/stores, exit and target syscalls; documented limits are eight parameters, six syscall arguments and a 2000-byte frame.
- Syscall numbers belong to the selected target; Linux ARM64/RISC-V use write=64, mmap=222, exit=93. Windows raw rejects syscall and exit; its entry returns to the loader.
- Diagnostics contain source excerpts and caret spans; fix type/name/mutability errors before running the output.
- Migrate an older source: `python3 toolchain/mayc/tools/migrate_strict.py old.may --write`; review added Any types and explicit returns before relying on the result.
- Language server implementation: [Maylang maylsp](../toolchain/maylsp/README.md); protocol/reference: [LSP guide](../docs/LSP.md).
- VS Code integration: [extension installation and settings](../editors/vscode/README.md); strict checking defaults on through `maylang.strict`; rebuild server/reload the window after toolchain changes.
- Package manager: [maypkg usage and manifest reference](../toolchain/maypkg/README.md); project manifests are mayproj.json, with mayproj.lock for dependency locking.
- Compiler/bootstrap verification: `toolchain/mayc/tests/run.sh`; source-only chain verification: `python3 toolchain/rust/test.py`.
- Additional language/runtime regressions: `python3 tests/compliance/run.py`.
- Networking verification: `python3 toolchain/mayc/tests/network.py --llvm`; live tests may skip when socket creation is disallowed; CI can require sockets.
- Documentation verification: `python3 reference/generate.py --check`; this checks reference freshness, declaration description coverage and pure-list Markdown format.
- More build/ABI/target details: [compiler guide](../toolchain/mayc/README.md), [native internals](../docs/NATIVE.md), [GC guide](../docs/GC.md), [source bootstrap](../toolchain/rust/README.md).
- Runnable reference verification: `python3 toolchain/tests/documentation.py`; tagged-release provenance and publishing: [installation](../docs/INSTALL.md).
