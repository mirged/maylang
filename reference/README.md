- **Maylang language and API reference** — a separate, list-only documentation set for the current self-hosted compiler and repository standard library.
- [Language guide](LANGUAGE.md) — syntax, values, typing, expressions, control flow, functions, modules, errors and native interfaces.
- [Syntax catalog](SYNTAX.md) — every keyword, type and operator in the maintained editor catalog, with signatures and examples.
- [Runtime API](RUNTIME.md) — built-in functions, methods, OS operations, math, memory and C calls.
- [Standard library index](STDLIB.md) — links to all library and portable-core API pages and their declaration counts.
- [Compiler and tooling](TOOLCHAIN.md) — build/run commands, CLI options, runtimes, targets, package management and editor integration.
- [Examples](EXAMPLES.md) — small strict-mode programs and links to complete repository examples.
- [Machine-readable inventory](inventory.json) — all top-level library and portable-core declarations with exact signatures, module names, kinds and source lines.
- Scope: strict self-hosted `mayc` is the default. Legacy syntax and limitations are labeled. Dynamic `Any` annotations in source are reproduced rather than replaced with invented static contracts.
- Format: every nonblank line of every documentation page is a top-level Markdown bullet. Examples are inline code; pages contain no tables, standalone prose, headings or fenced code blocks.
- API entries document actual source signatures, behavior and explicit fault strings where present. Private declarations are included for completeness and marked unavailable to importers.
- The compatibility native copy is detailed in [native](stdlib/native.md); active injected definitions live in `toolchain/mayc/native.may`. Portable APIs live in [core](stdlib/core.md) and common helpers in [prelude](stdlib/prelude.md); explicitly imported library modules have individual pages.
- Sources: [strict guide](../docs/STRICT.md), [compiler implementation](../toolchain/mayc/main.may), [standard library](../stdlib/), [editor catalog](../toolchain/maylsp/docs/reference.json), and the source links on each module page.
- Maintain curated API descriptions in [descriptions.json](descriptions.json); edit language/tooling/examples pages directly.
- Regenerate the syntax catalog, module pages, index and inventory from the repository root: `python3 reference/generate.py`.
- Check generated freshness, complete description coverage and the list-only format: `python3 reference/generate.py --check`.
- The generator has no third-party Python dependencies and does not edit existing documentation or language implementation files.
- Runnable examples are checked by `python3 toolchain/tests/documentation.py`; CI compiles and executes their actual inline source and all strict-guide fenced examples.
- The generated reference replaces the interactive guide, has no Node dependencies or lockfile, and requires only Python for generation.
- Update source declarations/descriptions, run both `python3 reference/generate.py` and `python3 toolchain/maylsp/docs/generate.py`, and commit synchronized outputs; CI checks both catalogs with `--check`.
